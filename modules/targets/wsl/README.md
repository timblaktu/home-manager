# WSL Target Module Documentation\n\nThe `targets.wsl` module provides Windows Subsystem for Linux (WSL) integration for Home Manager configurations.\n\n## Quick Start\n\n```nix\n# Basic usage\ntargets.wsl.enable = true;\n\n# With explicit username (recommended for pure configurations)\ntargets.wsl = {\n  enable = true;\n  windowsUsername = \"myuser\";\n};\n```\n\n## Configuration Options\n\n### Core Options\n\n#### `targets.wsl.enable`\n- **Type**: `bool`\n- **Default**: `false`\n- **Description**: Enable WSL integration\n\n#### `targets.wsl.windowsUsername`\n- **Type**: `nullOr str`\n- **Default**: `null`\n- **Example**: `\"tblack\"`\n- **Description**: Explicit Windows username. If null, will be captured from environment variables. Set this for pure configurations without `--impure` flag.\n\n### Computed Read-Only Options\n\n#### `targets.wsl.windowsUsernameFinal`\n- **Type**: `str` (read-only)\n- **Description**: Final computed Windows username from explicit setting or environment capture\n\n#### `targets.wsl.windowsHomeDir`\n- **Type**: `str` (read-only)\n- **Description**: Windows user home directory (e.g., `/mnt/c/Users/username`)\n\n#### `targets.wsl.wslDistroName`\n- **Type**: `str` (read-only)\n- **Description**: WSL distribution name (e.g., \"NixOS\", \"Ubuntu\")\n\n#### `targets.wsl.wslToWindowsUNC`\n- **Type**: `function` (read-only)\n- **Description**: Convert WSL paths to Windows UNC paths\n- **Example**: `wslToWindowsUNC \"/home/user\"` → `\"\\\\wsl.localhost\\NixOS\\home\\user\"`\n\n### Windows Tools\n\n#### `targets.wsl.windowsTools.enablePowerShell`\n- **Type**: `bool`\n- **Default**: `false`\n- **Description**: Enable PowerShell wrapper (provides both `powershell.exe` and `powershell` commands)\n\n#### `targets.wsl.windowsTools.enableCmd`\n- **Type**: `bool`\n- **Default**: `false`\n- **Description**: Enable cmd.exe wrapper (provides both `cmd.exe` and `cmd` commands)\n\n#### `targets.wsl.windowsTools.enableWslPath`\n- **Type**: `bool`\n- **Default**: `false`\n- **Description**: Enable wslpath utility wrapper\n\n## Use Cases\n\n### Pure Configurations (Recommended)\n\nFor reproducible builds without `--impure` flag:\n\n```nix\ntargets.wsl = {\n  enable = true;\n  windowsUsername = \"myuser\";  # Explicit username\n  windowsTools = {\n    enablePowerShell = true;\n    enableWslPath = true;\n  };\n};\n```\n\n### Environment Variable Capture\n\nFor development environments where environment variables are available:\n\n```nix\n# Requires --impure flag or nix-daemon with proper environment\ntargets.wsl = {\n  enable = true;\n  # windowsUsername = null;  # Will capture from environment\n  windowsTools.enablePowerShell = true;\n};\n```\n\n### Integration with Other Modules\n\nAccess computed values in other modules:\n\n```nix\n# Example: Configure application with Windows paths\nservices.myapp.configFile = pkgs.writeText \"config\" ''\n  windows_home = ${config.targets.wsl.windowsHomeDir}\n  username = ${config.targets.wsl.windowsUsernameFinal}\n'';\n\n# Example: Add Windows directories to allowed paths\nsome.option.allowedDirs = [\n  config.home.homeDirectory\n  config.targets.wsl.windowsHomeDir\n  \"${config.targets.wsl.windowsHomeDir}/Documents\"\n];\n```\n\n## Architecture\n\n### Environment Variable Capture\n\nThe module uses a two-stage derivation approach:\n\n1. **Source derivation**: Captures environment variables using `builtins.getEnv`\n2. **Processing derivation**: Reads captured values with fallbacks\n\nThis avoids `impureEnvVars` issues while maintaining purity when explicit values are provided.\n\n### Tool Wrappers\n\nWindows tools are wrapped as shell scripts that:\n- Provide both full names (`powershell.exe`) and short names (`powershell`)\n- Execute the actual Windows binaries via their mount paths\n- Are available during home-manager activation\n\n## Troubleshooting\n\n### Environment Variables Not Detected\n\n**Problem**: `windowsUsernameFinal` shows \"unknown\"\n\n**Solutions**:\n1. Set explicit `windowsUsername = \"myuser\"`\n2. Use `--impure` flag: `home-manager switch --impure --flake .#config`\n3. Ensure nix-daemon has access to Windows environment variables\n\n### Windows Tools Not Found\n\n**Problem**: PowerShell/cmd.exe commands fail\n\n**Solutions**:\n1. Verify Windows tools are at default paths:\n   - PowerShell: `/mnt/c/Windows/System32/WindowsPowerShell/v1.0/powershell.exe`\n   - cmd.exe: `/mnt/c/Windows/System32/cmd.exe`\n2. Customize paths using `powerShellPath`/`cmdPath` options\n3. Ensure C: drive is mounted at `/mnt/c`\n\n### Pure vs Impure Builds\n\n- **Pure builds**: Use explicit `windowsUsername`, fully reproducible\n- **Impure builds**: Capture environment variables, machine-specific\n- **Recommendation**: Use pure builds for production, impure for development\n\n## Examples\n\n### Development Environment\n\n```nix\ntargets.wsl = {\n  enable = true;\n  windowsUsername = \"developer\";\n  windowsTools = {\n    enablePowerShell = true;\n    enableWslPath = true;\n  };\n};\n\n# Add shell aliases for convenience\nprograms.bash.shellAliases = {\n  cdwin = \"cd '${config.targets.wsl.windowsHomeDir}'\";\n  explorer = \"explorer.exe .\";\n};\n```\n\n### Multi-User WSL Environment\n\n```nix\n# In flake.nix\nhomeConfigurations = {\n  \"user1@machine\" = mkHomeConfig {\n    windowsUsername = \"user1\";\n    # ... other config\n  };\n  \"user2@machine\" = mkHomeConfig {\n    windowsUsername = \"user2\";\n    # ... other config\n  };\n};\n```\n\n### Application Integration\n\n```nix\n# Configure VS Code to use Windows paths\nprograms.vscode.userSettings = {\n  \"terminal.integrated.defaultProfile.windows\" = \"PowerShell\";\n  \"terminal.integrated.profiles.windows\" = {\n    PowerShell = {\n      path = \"powershell.exe\";  # Uses WSL wrapper\n    };\n  };\n};\n\n# Configure git with Windows credential helper\nprograms.git.extraConfig = {\n  credential.helper = \"/mnt/c/Program\\\\ Files/Git/mingw64/bin/git-credential-manager.exe\";\n};\n```\n
